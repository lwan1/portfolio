Projects / Sequence Modeling

RNN Music Generation

Trained a character-level LSTM in PyTorch to learn the structure of Irish folk music written in ABC notation, then sampled the model autoregressively to compose entirely new playable tunes.

1024 LSTM Hidden Units
256 Embedding Dim
3K Training Iterations
Overview

Music in ABC notation is just text — a stream of characters encoding key, meter, and the notes themselves. That reframes composition as a next-character prediction problem: given the characters seen so far, what character comes next?

I built an LSTM-based recurrent neural network from the layers up (embedding → LSTM → linear) and trained it on thousands of Irish folk songs. At inference, the model is seeded with a single character and sampled one token at a time, feeding each prediction back as the next input to generate complete songs.

Goals
  • Build a character-level language model for raw ABC sheet music.
  • Define the RNN as an nn.Module: embedding, single-layer LSTM, linear head.
  • Implement batched sequence sampling and a masked cross-entropy loss.
  • Generate music autoregressively via multinomial sampling over the vocabulary.
  • Decode the generated ABC back into an audio waveform you can listen to.
Results
  • The trained model produces syntactically valid ABC — correct headers, bar lines, and repeat marks emerge on their own.
  • Cross-entropy falls from the untrained baseline of ln(vocab) toward fluent next-character prediction.
  • Generated snippets are extracted and synthesized to .wav at 88.2 kHz for playback.
  • Sampling (not argmax) is essential — greedy decoding collapses into repetitive loops.
Key Learnings
  • An LSTM's hidden + cell state is what carries long-range musical context across time steps.
  • The full vocabulary matters: meta-characters (titles, keys) increase task complexity.
  • Temperature trades off novelty against coherence — exactly the fluency/diversity tension.
  • Teacher forcing during training vs. autoregressive feedback at inference is a subtle but crucial distinction.

Training

Random seq_length=100 windows are drawn from the corpus; the target is the same window shifted one character right. Loss is CrossEntropyLoss over flattened (B×L, vocab) logits, optimized with Adam at lr=5e-3 for 3,000 iterations, with checkpoints saved every 100 steps and runs tracked in Comet ML.

Generation

Starting from the seed "X" (every ABC tune begins with X:), the model predicts logits, a softmax turns them into probabilities, and torch.multinomial samples the next character. The hidden state is carried forward each step, giving the model memory of everything generated so far.

Technical Challenges

                            
    
                                
  • Correctly aligning input/target windows so the model predicts the next character, not the current one.
    • 
                                
  • Reshaping LSTM outputs to (B×L, vocab) so cross-entropy can score every time step at once.
    • 
                                
  • Managing the LSTM hidden + cell state across autoregressive generation steps.
    • 
                                
  • Avoiding repetitive output — sampling from the distribution instead of taking the argmax.
    • 
                                
  • Extracting only well-formed song snippets from a long, sometimes-noisy generated stream.
    • 
                            

                        

                        

                            
Hyperparameters

                            
    
                                
  • Embedding dim 256, LSTM hidden size 1024, single layer.
    • 
                                
  • Sequence length 100, batch size 8, 3,000 iterations.
    • 
                                
  • Adam optimizer, learning rate 5e-3.
    • 
                                
  • Generation length 1,000 characters, seed string "X".
